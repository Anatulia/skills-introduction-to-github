# Come costruire un'azienda agentica con Claude Code (Dario Vignali + Pietro Virgilito)

## Cos'è
(fonte: video YouTube di Dario Vignali, ~1h24m, titolo originale "Come creare un'azienda agentica con gli Agenti AI di Claude Code (Dario Vignali)"; verifica comunque leggendo i file per il titolo/dettagli esatti)

## Di cosa parla
Dario Vignali intervista Pietro Virgilito (esperto di cybersecurity) che mostra dal vivo, dentro VS Code, un progetto di esempio di "azienda agentica": una piccola digital agency che usa Claude Code per gestire in automatico le richieste di preventivo dei clienti. Viene mostrata l'intera architettura: cartella di progetto con dati aziendali (listino prezzi ed agenda in Excel), script Python/Bash per i calcoli deterministici, file `CLAUDE.md` come "identità" sempre in memoria dell'agente orchestratore, e sotto-agenti specializzati definiti in `.claude/agents/` (analista, preventivatore, pianificatore, redattore, archivista). Il video alterna spiegazione teorica e demo pratica: a un certo punto fanno girare dal vivo l'intero flusso su una richiesta reale (sito web per uno studio di tatuaggi), mostrando l'orchestratore che attiva gli agenti in sequenza/parallelo fino a produrre l'email di preventivo pronta.

## A cosa serve / che problema risolve
Serve da riferimento pratico per progettare un sistema multi-agente reale con Claude Code, non solo teoria: mostra passo passo come strutturare cartelle, permessi, ruoli e regole per delegare processi aziendali (es. gestione preventivi) a un gruppo di sotto-agenti invece che affidarsi a un unico prompt/chat gigante. Utile da ripescare quando serve: (a) capire come impostare `CLAUDE.md` e la cartella `.claude/agents/`; (b) decidere quando far lavorare gli agenti in parallelo vs in sequenza; (c) capire dove tracciare il confine tra compiti "probabilistici" (linguaggio, creatività) e "deterministici" (calcoli, somme, dati) da delegare a script invece che al language model; (d) impostare `settings.json` con permessi minimi per evitare conferme manuali continue.

## Contenuti principali
- **Caso d'uso demo**: digital agency che deve rispondere a richieste clienti di sviluppo siti web con un preventivo (esempio concreto: richiesta di un sito per uno studio di tatuaggi, budget 3.000€, scadenza legata a un evento).
- **Architettura agentica**: un agente padre/orchestratore che non esegue lavoro ma lo assegna a 5 specialisti:
  - *Analista* — legge la richiesta cliente ed estrae una scheda/semantica standardizzata (solo permesso `Read`, principio dei privilegi minimi).
  - *Preventivatore* — calcola il costo usando esclusivamente il listino aziendale (Excel), delegando le somme a uno script Bash deterministico (mai calcoli "a mente" del language model).
  - *Pianificatore* — verifica la disponibilità/agenda aziendale (altro file Excel) e calcola le tempistiche di consegna.
  - *Redattore* — attende i risultati di preventivatore e pianificatore (lavorano in parallelo tra loro) e scrive l'email finale al cliente.
  - *Archivista* — salva l'output (in produzione potrebbe anche inviare l'email/WhatsApp/DB).
- **Struttura di cartelle del progetto**: `data/` (dati aziendali: listino, agenda), `script/` (tool Python/Bash atomici: lettura Excel, calcolo giorni mancanti, somma importi), `CLAUDE.md` (regole sempre in memoria, "identità" dell'orchestratore), `.claude/agents/*.md` (un file per sotto-agente, frontmatter YAML con `name`, `description`, `tools`), `.claude/settings.json` (permessi/allow-list per evitare conferme ripetute — man-in-the-loop).
- **Probabilistico vs deterministico**: i language model sono bravi con parole/creatività/ragionamento ma inaffidabili sui calcoli numerici su grandi volumi di dati → per operazioni matematiche/aritmetiche usare sempre script dedicati e "deterministici", mai far calcolare i totali al modello.
- **Principio dei privilegi minimi**: ogni sotto-agente riceve solo i `tools` strettamente necessari (es. l'analista ha solo `Read`, mai `Write`/`Bash`) per limitare i danni in caso di errore o comportamento anomalo dell'agente.
- **Isolamento dei sotto-agenti**: gli specialisti non comunicano direttamente tra loro, passano sempre per l'orchestratore, che fa da "passacarte" senza riassumere o alterare i risultati — pattern "verticale/gerarchico" (contrapposto al pattern multi-agente "orizzontale" con dialogo diretto tra agenti, in Claude Code = feature "Agent Teams", ancora in beta).
- **Parallelo vs sequenziale**: task indipendenti (preventivatore/pianificatore) vanno lanciati in parallelo per efficienza; task dipendenti (es. redattore che aspetta gli altri due) vanno in sequenza; attenzione alle race condition se più agenti scrivono sullo stesso file.
- **Consiglio su granularità**: non creare mega-agenti generici ("sei il mio assistente per tutto") — meglio tanti piccoli agenti con compiti atomici e ben delimitati, costruiti e validati incrementalmente nel tempo (analogia con la costruzione di un edificio: prima le fondamenta, poi si aggiunge complessità pezzo per pezzo).
- **Chi non sa programmare**: è comunque possibile far scrivere gli script a un LLM, facendoli poi validare/rivedere da un secondo modello (es. scritto con ChatGPT, verificato con Claude) per bug e problemi di sicurezza.
- **Demo dal vivo**: viene lanciata la richiesta reale via Claude Code da terminale (referenziando il file con `@nomefile.md`), si osserva l'orchestratore attivare in sequenza/parallelo i sotto-agenti fino a produrre l'email di preventivo finale salvata in `offerte/`.
